---

**Clousight Bench** 把公认基准——SWE-bench、TPC-DS/H、YCSB、TPC-C、MMLU、GSM8K、
HumanEval——**原样**跑在托管云产品与大模型 endpoint 上,并给出带可验证溯源链的
数字:哪个基准、哪份固定数据集、哪个 evaluator、跑在哪个被测系统上。

它从不二次打分、也不混合分数。基准自带的 harness 出结论;框架只补上可复现性簿记
与云产品维度(延迟、成本、逐项分数、可选的 LLM 判定)。

## 快速开始

<Steps>
<Step title="安装">
```bash
pip install clousight-bench          # 按需加 extra:[store] [llm] [tpcds] [swebench]
# 或从源码克隆:  uv sync --all-extras
```
</Step>
<Step title="看已注册了什么">
```bash
csbench list
```
所有已注册的 benchmark、evaluator、platform——外加一条可直接复制的"run one"提示。
</Step>
<Step title="跑一个——离线,无云,无密钥">
```bash
printf 'target:\n  mode: mock\n' > mock.yaml
csbench run --domain agent-runtime --benchmark swe-bench --platform local-sim --config mock.yaml
```
stdout 上得到 `status: completed` 记录。✅ 这是完整跑了一遍阶段机
(resolve → prepare → run → score → persist),基于内置 fixture——无云账号、无 API key。
</Step>
<Step title="对准真实系统(配置接入)">
```bash
printf 'target:\n  mode: runtime\n  endpoint: "https://dashscope.aliyuncs.com/compatible-mode/v1"\n  model: qwen-max\n  credentials_ref: env:DASHSCOPE_API_KEY\n' > qwen.yaml
export DASHSCOPE_API_KEY=...
csbench run --domain llm --benchmark mmlu --platform llm-endpoint --config qwen.yaml
```
同样的命令形状;现在数字来自你已在运行的 endpoint。之后 `csbench serve` 在
`http://127.0.0.1:8787` 打开 web 查看器。
</Step>
</Steps>

<Tip>
在 CI 里用阈值门控:`csbench run … --assert thresholds.yaml`,任一测量未达标即非零退出。
见 [pytest 与 CI](/docs/zh/pytest-ci)。
</Tip>

## 心智模型

三样东西,各自是一个由入口点发现的插件:

- **`BenchmarkSuite`** 包装一个公认 harness(或任意可复现负载):`resolve → prepare
  → run → mock_artifacts`。
- **`Evaluator`** 把运行产物变成命名空间化的 **`Measurement`**(以及可选逐项 **`items`**)
  ——一个纯粹、离线、可重打分的函数。
- **被测系统**由 `--platform` + 一个 `target` 选定:模拟参考、**你配置接入的已运行
  服务**(endpoint + 凭证)、或框架为你制备的云。

新增基准 = 写一个 Suite + Evaluator;运行 = `csbench run --benchmark <id>`。见
[新增一个 benchmark](/docs/zh/adding-a-suite)。

## 可复现性契约

每条记录带一个 `provenance` 块(benchmark id、固定数据集 digest、evaluator id、
`unmodified` 标记、scaffold)+ 三个独立指纹(`benchmark` / `environment` /
`implementation`),让你能判断两个数字是否可比。每条测量带一个 `reproducibility_class`:

| 类别 | 含义 |
|---|---|
| **deterministic** | 同输入同数字——如 `swe-bench.resolved`、`mmlu.accuracy` |
| **environmental** | 方法可复现;数字随网络/区域/账号漂移——成本、延迟 |
| **judge-based** | 有 LLM 判定参与——见 [判定](/docs/zh/judges) |

`official=true` 的测量是基准自身在 `<suite_id>.` 命名空间下的结论(一个溯源标记,
由 `csbench conformance` 强制);附加 [metrics](/docs/zh/metrics) 与社区 evaluator
待在各自的命名空间。结果始终**按维度——从不混合成一个分**。

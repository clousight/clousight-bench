**[Clousight](https://clousight.com) 的度量标尺 —— 原封不动地运行公认基准套件
(首个为 SWE-bench Verified),测的是受管云产品,每个数字都带可校验的来源链。**

Clousight Bench 从不重新计分、从不混合分数。判定由套件自己的 harness 产出;
框架补上**云产品维度**(运行时行为、延迟、轨迹、成本)和可复现性记账:
哪个套件、哪个固定数据集版本、哪个评测器、哪个脚手架 —— 全部折叠进可 diff 的内容指纹。

```
BenchmarkSuite.resolve → prepare → run   (套件自己的 harness,原封不动)
        ▼
Evaluator.evaluate(RawArtifacts)          (纯函数、离线、命名空间化的测量值)
        ▼
schema-0.3 记录 → csbench serve(Web 查看器)/ csbench query(SQL)
```

一切与套件或产品相关的东西都是插件。

## 可复现性契约

每条记录携带 `provenance` 块(套件 id、固定数据集版本、评测器 id、`unmodified`
标志、脚手架)以及三个独立指纹(`benchmark` / `environment` / `implementation`),
让你能判断两个数字是否可比。每个测量值携带 `reproducibility_class`:

| 类别 | 含义 |
|---|---|
| **deterministic** | 同输入同结果 —— 如 `swe-bench.resolved` |
| **environmental** | 方法可复现;数值随网络/地域/账号变化 —— 如成本、延迟 |
| **judge-based** | 判定链路中有 LLM 或人工 |

官方测量值(`official=true`)是上游套件自己的判定,置于套件命名空间下;
自定义评测器被结构性地约束在自己的命名空间。结果永远**按维度呈现,绝不混分**。

## 快速开始(无需云账号、无需 docker)

```bash
pip install clousight-bench
csbench list                       # 已注册的套件、评测器、适配器

# 以 mock 模式把 SWE-bench Verified 跑过完整的 stage 机器:
cat > mock.yaml <<'EOF'
target:
  mode: mock
EOF
csbench run --domain agent-runtime --benchmark swe-bench \
    --platform local-sim --config mock.yaml

# 打开 Web 查看器(中英切换、深浅主题、轨迹瀑布图):
csbench serve
```

mock 运行走的是真实代码路径,基于套件自带的 fixture 产出 schema-0.3 记录;
`csbench serve` 在 `http://127.0.0.1:8787` 渲染。可选分析存储(Parquet + DuckDB):
`pip install clousight-bench[store]`。

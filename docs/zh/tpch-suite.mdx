TPC-H 运行在 `data-warehouse` 域的 `duckdb-local` 参考平台上（无 provider 的单机引擎，是
`tpc-ds` 套件的兄弟）。通过 `params.mode` 选择两种模式：

- **`reference`**（默认）—— 单流跑一遍 22 条查询，对每个结果取摘要，产出 `queries.json` +
  `summary.json`。便宜的 CI/离线路径，由 `official-tpch-evaluator` 评分。
- **`official`** —— 完整官方全流程（Load → Power 含 RF1/RF2 → 多流 Throughput → ACID），
  产出 `official.json`，由 `official-tpch-qphh-evaluator` 算出官方 **`QphH@Size`** 复合分。

<Note>
官方模式的数字复现官方 TPC-H 公式，但**未经审计**：无 TPC 会员、无审计、无带报价的完整披露报告。
RF1/RF2 刷新集由 clousight 生成。每个分数都会在 `notes` 里注明。
</Note>

## 运行参考模式（无需云账号）

```bash
# 离线 mock 路径 —— 无需 DuckDB，跑通整个阶段机：
printf 'target:\n  mode: mock\n' > mock.yaml
csbench run --domain data-warehouse --benchmark tpc-h \
  --platform duckdb-local --config mock.yaml

# 真实 DuckDB SF1 运行（需要 [tpch] extra：pip install clousight-bench[tpch]）：
printf 'target:\n  mode: runtime\nparams:\n  scale_factor: 1\n  query_ids: [1, 6, 14]\n' > real.yaml
csbench run --domain data-warehouse --benchmark tpc-h \
  --platform duckdb-local --config real.yaml
```

## 运行官方模式（QphH@Size）

官方模式需显式选择其 evaluator（两个 evaluator 都支持 `tpc-h`，默认选参考那个）：

```bash
# 离线 mock 官方全流程：
printf 'target:\n  mode: mock\nparams:\n  mode: official\n  evaluator: official-tpch-qphh-evaluator\n' > off-mock.yaml
csbench run --domain data-warehouse --benchmark tpc-h \
  --platform duckdb-local --config off-mock.yaml

# 真实 DuckDB 官方运行（需要 [tpch] extra）：
printf 'target:\n  mode: runtime\nparams:\n  mode: official\n  scale_factor: 1\n  streams: 2\n  evaluator: official-tpch-qphh-evaluator\n' > off-real.yaml
csbench run --domain data-warehouse --benchmark tpc-h \
  --platform duckdb-local --config off-real.yaml
```

`params.streams` 默认取该 scale factor 的官方最小值（SF1 → 2）。查询流排列来自官方
Appendix A 表（`suites/tpc_h/fixtures/query_order.json`）；`streams > 2` 时请从该表扩展。

## 官方模式测量的维度

`official-tpch-qphh-evaluator` 产出这些 `tpc-h.*` 测量：

| 测量 | 含义 | reproducibility_class |
| --- | --- | --- |
| `tpc-h.qphh_at_size` | **QphH@Size** = `sqrt(Power@Size · Throughput@Size)` | `environmental` |
| `tpc-h.power_at_size` | `Power@Size` = `(3600 / geomean(24 个区间)) · SF` | `environmental` |
| `tpc-h.throughput_at_size` | `Throughput@Size` = `(S · 22 / Ts) · 3600 · SF` | `environmental` |
| `tpc-h.load_time_s` | 数据装载墙钟 | `environmental` |
| `tpc-h.queries_passed` | 对钉定 SF1 参考的通过率（Power 流；仅 SF1） | `deterministic` |
| `tpc-h.acid_atomicity` / `_consistency` / `_isolation` | `1.0` pass / `0.0` fail | `deterministic` |

ACID Durability 报为 `n/a`（嵌入式 DuckDB 无崩溃/恢复夹具），故不进入测量集。ACID 是独立的
pass/fail 门，**不**参与 `QphH@Size` 复合分。

所有测量都带 `official=True` —— 这是一个*溯源*标记（"由套件公认的 evaluator 产出"），并非审计声明；
是否会漂移由 `reproducibility_class` 承载。

## 暂不在范围内

`price/QphH`（公式接缝已留；系统报价输入尚未接入）、真实 SUT 的 `config-connect` 引擎（目前仅
duckdb-local）、以及 SF ≥ 100 的规模验证。嵌入式 DuckDB 不测 Durability 崩溃恢复。
